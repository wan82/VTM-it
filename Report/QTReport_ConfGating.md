# QTReport · 置信度门控 + 双向早停 —— 方法与对比

本报告聚焦最近一次改动的**核心方法与算法 pipeline**，并把**原方案（基础 QT 早停）**与
**改动方案（置信度门控 + 双向早停）**从「方法」和「结果」两个层面做对比。

---

## 1. 要解决的问题

基础版的 QT 早停（只按预测深度封顶 QT）有两个毛病：

- **不分确信度，一律早停** → 模型不确定时也硬停，造成质量损失（实测 QP37 掉 0.37 dB）；
- **只封上界、不利用下界** → 低 QP 下 CTU 本来就要深分，早停几乎不触发，省不到时间。

改动方案用**置信度门控**解决前者、用**双向早停**解决后者。

---

## 2. 算法 Pipeline

整个方法分两段：① 推理（把一个 CTU 变成「预测深度 + 置信度」）；② 编码器决策（据此早停）。

### 2.1 推理 pipeline（每个 128×128 CTU，一次）

```
读入 CTU 原始亮度(128×128)
        │  统一缩放到 10bit（与训练一致：out = in << (10 - bitDepth)）
        ▼
提取 5 个空域特征：Sobel_mean, Sobel_std, Lap_std, std, Lap_mean
        │
        ├─ 由 POC 和基础QP 推 QP-value（VTM RA, GOP=32: POC%32→TID→偏移）
        ▼
组装特征向量 = [5 个空域特征, 匹配的 QP-value]      （顺序与训练一致）
        │  按基础QP(22/27/32/37)选对应的森林/决策树
        ▼
森林推理：每棵树遍历到叶子 → 累加类别概率 → argmax
        ▼
输出：预测 qt_max（0..4） + 置信度 conf（= 预测类别的概率，0..1）
```

> C++ 推理的**类别与置信度**都与 sklearn `predict` / `predict_proba` 逐样本一致（验证 600/600）。

### 2.2 编码器决策 pipeline（嵌在 EncCu 的划分递归里）

```
进入一个 CU 的 xCompressCU
        │
   是 CTU 根? (currQtDepth==0 && currMtDepth==0, inter, 完整128, 非边界)
        │ 是                                   │ 否
        ▼                                       │
  跑推理 → (qt_max, conf)                        │（沿用本CTU根算出的预测）
        │                                       │
  ┌── 置信度门控 ───────────────┐                │
  │ conf ≥ 阈值(默认0.7)?        │                │
  │   否 → 不介入(全搜)，本CTU结束 │                │
  │   是 → 启用早停              │                │
  └──────────────┬─────────────┘                │
                 ▼                               ▼
        ┌────────────── 模式循环(每个待测模式) ──────────────┐
        │  ① 下界·强制分（仅 CTU 根且 qt_max≥1）：             │
        │     跳过 128 大块的块模式 + BT/TT，只测 QT          │
        │  ② 上界·封顶（任意层）：                            │
        │     currQtDepth ≥ qt_max 且是 QT 划分 → 跳过该 QT   │
        │  ③ 其余模式：正常 RDO                              │
        └───────────────────────────────────────────────────┘
```

**两条早停规则的依据与安全性：**

| 规则 | 触发条件 | 作用 | 为什么安全 |
|------|----------|------|-----------|
| **上界·封顶** | `currQtDepth ≥ 预测qt_max` 且测 QT | 不再测更深 QT | 真值里没有比 qt_max 更深的划分 |
| **下界·强制分** | CTU 根 且 `qt_max ≥ 1` | 跳过 128 大块的块/BT/TT，只走 QT | `qt_max≥1 ⟺ 128 必被划分`，根层一定成立 |
| **置信度门控** | `conf ≥ 阈值` 才启用上两条 | 不确信就全搜 | 把高风险（易错）的 CTU 排除在早停之外 |

> 块模式与 BT/TT 被跳过时，`bestCS` 仍由强制的 QT 递归填上，不会出现空结果/崩溃。
> 边界 CTU / intra / 不确信 / 未设模型 → 完全不介入，行为同原版。
> 可调环境变量：`QT_FOREST_CONF`（阈值，默认 0.7）、`QT_FOREST_FORCE`（下界开关，默认 1）。

## 3. 方法层面对比

| 维度 | 原方案（基础 QT 早停） | 改动方案（门控 + 双向） |
|------|------------------------|--------------------------|
| 方向 | 单向：只封上界（QT 封顶） | **双向**：上界封顶 + 下界强制分 |
| 是否看确信度 | 否，一律早停 | **是**，conf ≥ 阈值才早停 |
| 低 QP 省时来源 | 几乎没有（封顶很少触发） | **下界强制分**跳过 128 大块 RDO |
| 高 QP 质量风险 | 高（不确定也硬停） | **低**（门控挡掉不确信的） |
| 可调性 | 无 | `QT_FOREST_CONF` / `QT_FOREST_FORCE` |
| 本质 | Pareto 前沿上一个固定、偏激进的点 | 把"激进动作"限制在"确信"时做 → 更靠近无损 |

一句话：**原方案是"无脑早停"，改动方案是"确信才动手、且两头都省"**。

## 4. 结果层面对比（BQSquare，33 帧，QP 22/27/32/37）

> 时间节约统一记为「正=更快」便于对比（报告文件里现在用负值表示更快）。

### 4.1 逐 QP

| QP | 方案 | 快kbps vs 原 | 快Y-PSNR vs 原 | 省时 |
|----|------|--------------|-----------------|------|
| 22 | 原 | 1497.29 (+0.09%) | 39.6722 (+0.014) | 2.2% |
| 22 | **新** | **1495.99 (持平)** | **39.6581 (持平)** | **3.9%** |
| 27 | 原 | 802.40 (−0.04%) | 36.5340 (持平) | 0% |
| 27 | **新** | **802.71 (持平)** | **36.5338 (持平)** | **2.8%** |
| 32 | 原 | 465.50 (+0.11%) | 33.3776 (−0.028) | 7.9% |
| 32 | **新** | **464.97 (持平)** | **33.4060 (持平)** | **2.3%** |
| 37 | 原 | 283.64 (+0.48%) | 30.3525 (**−0.37**) | 25.0% |
| 37 | **新** | 281.99 (−0.10%) | 30.6980 (**−0.025**) | 18.3% |

### 4.2 汇总

| 指标 | 原方案 | 改动方案 |
|------|--------|----------|
| BD-rate | +0.92% | **≈ 0**（三个 QP 完全持平、QP37 近中性） |
| 平均省时 | ~8.8% | ~6.8% |
| QP37 质量损失 | −0.37 dB | **−0.025 dB** |
| 低/中 QP 输出 | 略有扰动 | **比特流完全不变** |

### 4.3 解读

- **改动方案把 QP22/27/32 变成了"输出一模一样、只是更快"** —— 跳过的全是"反正会被剪掉/选不上"的搜索，**零质量代价的纯省时（真正的免费午餐）**。
- **QP37 的质量损失从 0.37 dB 收回到 0.025 dB**，靠的就是置信度门控挡掉了不确信的早停；代价是省时从 25% 降到 18%。
- **净效果**：用约 2 个百分点的省时，换回了几乎全部 BD-rate —— 从 `+0.92% / 8.8%` 移到了
  `≈0 / 6.8%`，是一个**接近无损**的工作点。

> 注意：每帧 ET 是整数秒，低省时（2~4%）含取整噪声，属小而真实的信号；QP37 的 18% 是大头。
> 单序列 33 帧，结论是指示性的，需更多序列/帧才能定论。

---

## 5. 小结与下一步

- 方法上：**置信度门控 = 保 BD-rate 的闸**，**下界强制分 = 多省时间的油门**，两者组合把"激进省时"
  限制在"模型确信"时进行，从而在几乎不动 BD-rate 的前提下拿到省时。
- 现在 BD-rate ≈ 0，**还有 headroom**：
  1. **调低 `QT_FOREST_CONF`（0.7→0.6→0.5）** —— 更多 CTU 过闸、省更多时间，观察 BD-rate 何时开始上升（零成本调参）；
  2. **MTT 预测** —— 低 QP 的时间大头在深层 BT/TT 递归，下界只跳了 128 一层；要进一步提升低 QP 省时需扩展 MTT 标签与模型。
